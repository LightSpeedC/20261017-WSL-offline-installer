## 1. 決定事項

| 項目 | 決定 |
|---|---|
| WSL 本体 | ビルドするたびに**その時点の最新版**を取ってくる（版数は固定しない） |
| ディストリビューション | Ubuntu 24.04 だけ |
| 導入側の OS | Windows 11 だけ |
| 導入側の GPU | ビルド用の PC と同じ世代（Intel Iris Xe ＋ NVIDIA RTX 30 系のノート PC 用）を想定 |
| llama-server | CPU・NVIDIA（CUDA）・Intel（SYCL）の 3 通りを、最新の llama.cpp からビルドして Ubuntu の中に入れる |
| AI エージェント | オンプレのオフライン llama-server につないで使う |
| Linux の中身 | ビルド側で apt のパッケージを入れておき、`wsl --export` で書き出したものを配る |
| フォルダ構成 | 共通ルールのフォルダ構成は使わない。`prepare/`・`bundle/`・`installer/` を使い、計画は `notes/` に置く |

## 2. フォルダ構成

```text
prepare/     ビルド側のスクリプト（取得・準備・書き出し・まとめ）
bundle/      集めたもの（Git には入れない）
  wsl/         WSL の msi（x64）
  distro/      準備済みの Ubuntu（.tar.gz）
  manifest.json  版数・SHA-256・取得日時
installer/   導入側のスクリプト（install.cmd ＋ install.ps1）
notes/       計画・状態
_releases/   installer と bundle をまとめた zip（Git には入れない）
```

## 3. ビルド側（prepare/）

### 1. fetch-wsl.ps1 ― 最新の WSL を取得

- GitHub API の `repos/microsoft/WSL/releases/latest` から、`*.x64.msi` の資産を探して取得する（プレリリースは除く）
- 版数・ダウンロード元・SHA-256 を `manifest.json` に書く。同じ版がすでにあれば取り直さない

### 2. prepare-distro.ps1 ― Ubuntu を準備して書き出す

- ビルド用の名前（`wsl-offline-build`）で、Ubuntu 24.04 を一時的に入れる
- 入れるパッケージの一覧は `prepare/packages.txt` に置き、`apt update` → `apt full-upgrade` → 一覧を `apt install` の順に実行する（初期値: `build-essential` `git` `curl`）
- 既定のユーザで、ホームに nvm を入れ、nvm で Node.js を入れる。Node.js の版は `prepare/node-version.txt` の 1 か所に置く（初期値: 26.11。実在する版かは実装するときに確かめる）
- AI エージェントは `prepare/npm-global.txt` の一覧を `npm install -g` で入れる。どれもホーム配下に入るので、書き出しに含まれ、導入先ではネット無しで起動できる。初期値: `@anthropic-ai/claude-code` `@openai/codex` `@mariozechner/pi-coding-agent` `opencode-ai` `openclaw` `@google/gemini-cli` `@github/copilot` `@qwen-code/qwen-code` `@moonshot-ai/kimi-code`
- npm で配られていないもの（Antigravity CLI `agy`）は、提供元の導入スクリプトで既定のユーザのホーム（`~/.local/bin`）に入れる
- ユーザ名とパスワードは、ビルド用の Ubuntu を初めて起動したときに表示される入力欄で、利用者が入力する。スクリプトは名前を持たず、`etc/_default_user.txt` も使わない。**パスワードは引数・ファイル・ログ・環境変数のどこにも残さない**
- その既定ユーザの設定は書き出しに含まれない見込みのため（未検証）、`/etc/wsl.conf` の `[user]` に `default=<名前>` を書く。名前は Ubuntu の中で UID 1000 のユーザから取り、画面にもログにも出さない
- `apt clean` で掃除したあと `wsl --export` で書き出し、ビルド用のディストリビューションは `--unregister` で消す

### 2-1. llama-server を 3 通りビルドして入れる

- llama.cpp は、ビルドするたびに最新のリリースを使う。使った版は `manifest.json` に残す
- ビルド用の Ubuntu の中で 3 通りにビルドし、`/opt/llama.cpp/cpu`・`/opt/llama.cpp/cuda`（NVIDIA、CUDA）・`/opt/llama.cpp/intel`（Intel、SYCL ＋ oneAPI）に置く
- CUDA Toolkit と oneAPI の開発用一式は、ビルドが済んだら外し、実行に要るライブラリだけを残す
- GPU のドライバは WSL の中には入れず、Windows 側のものを使う

### 2-2. Windows 用の GPU ドライバを持って行く

- `prepare/fetch-drivers.ps1` で、NVIDIA（GeForce、ノート PC 用も含む）と Intel（Arc・Iris Xe）の Windows 用の最新ドライバを `bundle/drivers/` に取得する。版と SHA-256 は `manifest.json` に書く
- 最新版を自動で探せない場合は、提供元のページから手で取得して `bundle/drivers/` に置く手順にする（実装するときに確かめる）
- このビルド用の PC（Iris Xe ＋ RTX 3050 Ti Laptop）にも、同じドライバを先に入れ、llama-server の 3 通りの動作をここで確かめる

### 2-3. オンプレの llama-server へつなぐ設定

- 導入先では、オフラインで動く llama-server（OpenAI 互換の API）だけにつなぐ。接続先の URL とモデル名は、導入するときに `install.ps1` の引数で受け取り、各エージェントの設定ファイルへ書く。URL をビルド時の値として配布物に埋め込まない
- エージェントごとに、llama-server へつなげるか、どこに何を書けばよいかを、実装の前に 1 つずつ実際に試して確かめる（下の表は見込みで、未検証）
- 更新の確認・テレメトリ・ログインの促しは、オフラインでは失敗するか待たされるため、設定で止められるものは止める

| エージェント | 見込み（未検証） |
|---|---|
| OpenCode ／ Pi ／ OpenClaw ／ Qwen Code ／ Codex CLI | OpenAI 互換の接続先を設定できる見込み |
| Claude Code | Anthropic 形式の API が要る。llama-server がこの形式を受け付けるか、間に変換を挟むかを確かめる |
| Kimi Code | 接続先を変えられるかを確かめる |
| Gemini CLI ／ Copilot CLI ／ Antigravity CLI | 提供元のサービスへのログインが前提で、llama-server へはつなげない見込み。つなげなければ、入れるかどうかを改めて決める |

### 3. package.ps1 ― 配布物にまとめる

- `installer/` と `bundle/` を 1 つの zip にして `_releases/` に出す。zip の名前には WSL の版数と日付を入れる

> [!NOTE]
> **注意:** zip が 2 GB を超えると、扱えないツールがあります。大きくなった場合は、`.tar.gz` を zip に含めずに別ファイルで配るかどうかを、そのとき決めます。

## 4. 導入側（installer/）

`install.cmd` をダブルクリックすると、`install.ps1`（Windows PowerShell 5.1）が次の順に進みます。ネットにはつなぎません。

1. 管理者に昇格する
2. Windows 11 かどうか、仮想化がファームウェアで有効かを確認する。足りなければ理由を示して止める
3. `manifest.json` の SHA-256 と、手元のファイルが一致するかを確かめる
4. Windows の機能 `VirtualMachinePlatform` を有効にする。再起動が必要なら、再起動したあとに続きから進むよう登録して再起動を促す
5. WSL の msi を `msiexec /i … /qn` で入れる。入っている版が同じか新しければ飛ばす
6. `wsl --set-default-version 2` を実行する
7. NVIDIA・Intel の GPU が載っていれば、入っているドライバの版を調べ、持って来たものより古ければ、そのドライバを無人で入れる（GPU が無ければ飛ばす）
8. `wsl --import <名前> <置き場> <tar.gz>` で Ubuntu を入れる。同じ名前がすでにあれば飛ばす（入れ直すときは引数で指定する）
9. 引数で受け取った llama-server の URL とモデル名を、各エージェントの設定ファイルへ書く。llama-server へつながるかを確かめる（つながらなくても導入は止めず、警告にする）
10. `wsl -l -v` と、ディストリビューションの中で簡単なコマンドを実行し、動くことを確かめる

- 導入先のフォルダと名前は引数で変えられるようにする（既定値は `%LOCALAPPDATA%\wsl\Ubuntu-24.04-offline` と `Ubuntu-24.04`）
- 何度実行しても同じ結果になるようにする
- `wsl.exe` の出力は UTF-16 のため、そのまま読むと 1 文字おきに空白が入って化ける。結果を読んで判断する箇所は、環境変数 `WSL_UTF8=1` を付けて UTF-8 で出させてから読む。`chcp` は使わない
- 検証で Git Bash から呼ぶと、`/i` のような `/` で始まる引数がパスに書き換えられる（`/i` → `I:/`）。`msiexec` などは PowerShell・cmd から呼ぶ。Bash から呼ぶときは `MSYS_NO_PATHCONV=1` を付ける
- 処理の記録を、日本語のログに残す

## 5. 検証と実装順

### 実装する順（1 つずつ確認しながら進める）

1. 初期化（`git init -b develop`、`.gitignore`、文字コードと改行の定義ファイル）
2. `fetch-wsl.ps1`
3. `prepare-distro.ps1` と `packages.txt`
4. `install.ps1` と `install.cmd`
5. `package.ps1`

### 検証

- ネットを切った Windows 11 の VM（Hyper-V、入れ子の仮想化を有効にしたもの）で試す
- 試す場面は 3 つ: WSL が入っていない状態から ／ 古い WSL が入っている状態から ／ 一度入れたあとの 2 回目の実行
